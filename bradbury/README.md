## Why a separate build

Bradbury Phase 2 runs GenVM v0.6; Studio runs GenVM v0.2. The contract logic is the same; only the SDK dialect differs. [`port.py`](port.py) makes the Bradbury build from the Studio source, following the same rules as GenLayer Foundation's own Studio/Bradbury build targets:

- header `# { "Seq": [{"Depends": "py-genlayer:babwp9t3…zxa0"}] }`;
- `import genlayer as gl` plus explicit `genlayer.storage` and `genlayer.types` imports instead of `from genlayer import *`;
- `gl.Contract` → `gl.contract.Contract`, `gl.vm.run_nondet_unsafe` → `gl.vm.run_nondet`, `gl.message_raw` → `gl.message.raw`, `gl.get_contract_at` → `gl.contract.get_at`;
- docstrings and comments stripped, so each deploy fits Bradbury's per-transaction gas limit.

`port.py` asserts the output's syntax tree equals the source's after exactly these renames, and fails if a Studio-only construct remains. The four files in [`build/`](build/) are regenerated byte for byte by it.

**Tests on GenVM v0.6:** the unchanged test files pass against the Bradbury builds with genlayer-test 0.30.0rc2 (`pip install --pre genlayer-test==0.30.0rc2`, `GENVM_VERSION=v0.6.0-rc10`) and the v0.6 helper [`tests/conftest_v6.py`](tests/conftest_v6.py): **145** MeterReader and **132** RuleCheck plus gate tests. Before deploying, each build passed a free load check on Bradbury (`gen_call` with type `deploy`: the network's GenVM runs the constructor without a transaction, [`tools/loadcheck.mjs`](tools/loadcheck.mjs)).

## Reproduce

```bash
cd bradbury && npm install
# genlayer-js 2.0.0-rc.2 estimates fees without a sender, which fails on Phase 2; pass the account:
sed -i 's/publicClient.call({ to: address, data, gasPrice: receiptGasPrice/publicClient.call({ account: client.account?.address, to: address, data, gasPrice: receiptGasPrice/' node_modules/genlayer-js/dist/index.js
python3 port.py ../meter-reader/contracts/meter_reader.py build/meter_reader.py   # and the other three
node tools/loadcheck.mjs build/meter_reader.py build/rule_check.py
cd tools && BRADBURY_KEY_FILE=<throwaway key file> ../../venv/bin/python live_mr.py
BRADBURY_KEY_FILE=<throwaway key file> ../../venv/bin/python live_rc.py
```

Writes go to the GenLayer RPC `https://rpc-bradbury.genlayer.com` with protocol fees from `estimateTransactionFees`. Bradbury receipts carry no return value, so the scripts read results back with each contract's views; a view read right after a write can lag, so ids are confirmed from the chain ([`tools/reconcile_mr.py`](tools/reconcile_mr.py)).
