# ReportReader

A reusable GenLayer Intelligent Contract that turns a company's published periodic report into **exact on-chain figures** that other contracts can use: revenue for an earn-out, EBITDA and debt for a covenant test, net asset value for a performance fee. The figures are data, not code: anyone registers a report with the figures they need, and each period's report has **one official reading**.

**Live on GenLayer Studio:** see [Live results](#live-results-on-studio) · contract: [`contracts/report_reader.py`](contracts/report_reader.py) · consumer example: [`examples/consumer/earn_out_example.py`](examples/consumer/earn_out_example.py) · MIT

## The problem

Earn-outs, covenant tests, performance fees and revenue shares all pay on a few figures in a report the company publishes every period. Today someone reads the report and keys the numbers in by hand. Mistakes, delays and "what the report says" arguments all happen at that step, and a contract that wants to pay on the figure has no way to read it.

Asking a model "did the company hit its target?" turns a number into an opinion. ReportReader keeps the jobs apart:

- **The model only copies.** Every validator renders the page, and its model fills a fixed form: each figure's value exactly as printed, its scale and the words that state the scale, its line label, and whether the page shows it more than once.
- **Code decides.** Plain Python checks every copy against the frozen report and against the validator's own copy of the page, converts with integers only, and rounds once in the direction the report's owner chose.
- **Validators agree exactly.** They accept the leader's reading only if the outcome kind, the reason code and every figure are identical to their own.

## How it works

1. **Register** a frozen report with `register_report(spec_json)`:

   | Field | Meaning |
   |---|---|
   | `issuer_name` | The company name the page must print (compared as whole words; at least 3 letters). |
   | `url_template` or `page_urls` | Either the page address with `{n}` for the period number, in the path, or a frozen list of one address per period (for real addresses such as `/results/q3-2026`; each period its own page). `https://` and public hosts only; no query or fragment. |
   | `currency` | An ISO code from `get_rules()`. The page must print the code (or `€` for EUR, `£` for GBP). |
   | `period_ends` | 1 to 24 times, `YYYY-MM-DD HH:MM` in UTC, strictly increasing. |
   | `publish_lag_minutes` | When a period's report is due after its end; its reading window opens then. Real reports: weeks. |
   | `read_window_minutes` | How long the window stays open (at least 30). |
   | `figures` | 1 to 8 figures (below). |

   Each figure has a `key`, a short `label_hint` for the model (letters, digits and simple punctuation only), a **closed list of `labels`** (1 to 6 line labels it may be printed under, each at least 3 characters with 2 letters; the order does not matter), `ltm` (must the page label it as the last twelve months?), `decimals` (stored units are 10^-decimals of a currency unit), `step` (a power of ten in stored units), `rounding` (`down` or `up`, so the user picks the cautious side), `per_share` (see below) and `sign`:
   - `as_printed`: brackets or a minus sign mean negative;
   - `magnitude`: the absolute value (debt printed in brackets);
   - `finance_cost`: net finance cost positive, net finance income negative, decided from the line's own label by the rule PrivateCreditGate's four reviews shaped (see the contract).

   `per_share` (`true` or `false`, required, no default) says whether the figure is an amount per share or unit (earnings per share, net asset value per share, a distribution per unit) or a total. It must agree with the wording: a figure whose labels or hint read as per share (a share word within five words after `per`: `per share`, `per diluted common share`, `per A Accumulation share`, `per unit`, `per ADS`, `per common stock`; or `EPS`, `DPS`, `NAVPS`, `BVPS`, `DPU`, `NAVPU`, `/share`, `/unit`) must be `per_share: true`, and a figure with `per_share: true` needs a label or hint that reads so. For a per-share row whose label says nothing (`Diluted` under `Net income per share:`, `Class A` under a `Net asset value per share` heading), put the wording in the hint (`Net income per share, diluted`). The register cannot tell a wording it does not know: an author who writes a per-share row as a total with no per-share word in its labels or hint makes it a total.

   The specification is stored as canonical JSON with its **sha256 digest**. A consumer pins the report id **and** the digest. Nothing can be changed later: register a new report instead.

2. **Read** with `read(report_id, n)` during period `n`'s window. Anyone may call it. A call before the window opens is refused. The first `READ` in the window is the period's **official reading**; nothing replaces it.
3. **Consume** with `get_reading(report_id, n, at)`, passing the consumer's own time. It returns the status, the period end (`end`, `end_ts`), whether an official reading exists (`has_official`), the report's clock, so a consumer can refuse to sign up once the outcome can be known, and **`finalized`**: true once the network has finalized the transaction that made the answer final (see [Finality](#finality-marked-by-the-reader-itself)). Pay only on `finalized: true`. The status is one of:

   | Status | Meaning | Final? |
   |---|---|---|
   | `NOT_DUE` | The period has not ended. | no |
   | `WAITING` | Ended; the report is not due yet (publishing lag). | no |
   | `OPEN` | The reading window is open and has no `READ` yet. | no |
   | `CLOSING` | The window has closed, but no write stamped at or after the close has been processed yet, so a `READ` stamped before it could still land. Anyone may call `tick(report_id)`. | no |
   | `READ` | The official reading, with every figure as a decimal string in its stored units. | **yes** |
   | `MISSING` | The window closed with no `READ`. | **yes** |

   In ReportReader's logic `READ` and `MISSING` never change once reached. `finalized` turns true a little later, once the network has finalized that answer; from then on it cannot change for any consumer.

### Outcomes of a reading

| Kind | When |
|---|---|
| `READ` | Every figure read cleanly. Stored and binding if it is the first in the window. |
| `NOT_PUBLISHED` | The page clearly says the period's report is not published yet. Recorded; binds nothing. |
| `NO_READING` · `N1_PAGE_DARK` / `N1_WRONG_PAGE` | Empty page or fetch error; the issuer's name is not printed on the page or not copied; only other periods, an error or login page. |
| `NO_READING` · `N3_NOT_FINAL` | The figures are marked draft, preliminary, estimated or subject to change. |
| `NO_READING` · `N2_WRONG_PERIOD` / `N2_CURRENCY` | The period end (to the minute, in UTC) or the currency is not the report's, in the model's copy **or on the page itself**; or the page also prints a later period end of the same report. |
| `NO_READING` · `N2_LABEL` | A figure's copied line label is not on its closed list. |
| `NO_READING` · `N2_NOT_ANCHORED` | On the validator's own copy of the page, the label does not start a line or cell, or the copied value is not the first amount after it on the same line, as printed with its sign (see below). |
| `NO_READING` · `N2_NOT_LTM` | An LTM figure whose own line does not say LTM, TTM or last (trailing) twelve months before the value, whatever the model answers. |
| `NO_READING` · `N2_UNITS_MISSING` | No scale, or the copied scale is not the one the figure's line or the page's heading names, or the page names another scale; a total copied in whole units; a figure in pence or cents. |
| `NO_READING` · `N2_CONFLICT` / `N2_FIGURE_MISSING` / `N2_FINANCE_LABEL` | Two candidate figures; a missing figure; a finance-cost label the sign rule cannot read. |
| `NO_READING` · `N2_FORMAT` | An ambiguous number (`12.450`, `6,28`, `40'000`, an exponent), a page with decimal commas, a figure too large, a footnote number glued to a word on the figure's line (below), or a model answer that is not a JSON object. Refused, never guessed. A JSON number in the answer is read as the digits it was written with. |

Attempts are counted without limit; the first 20 are kept with their outcome.

## Why this equivalence check

GenLayer validators each run the non-deterministic step and decide whether to accept the leader's result. ReportReader's validator function first re-checks the leader's result shape (`_check_outcome`: known kind and reason, exactly the report's figure keys, each an integer that is a whole multiple of its step, magnitudes not negative), then reads the page itself and compares (`_same_outcome`) **exactly**: the kind, the reason of a `NO_READING`, and every figure.

**Exact, not a tolerance.** A GenLayer steward rejected an earlier contract of ours (MeterReader v1) because validators accepted values within a tolerance and the leader's values were stored, so two acceptable readings could pay a consumer differently. Here each figure is rounded once, to the report's step, before comparison; two copies that differ only below the step store the same number and agree, and any other difference means no agreement. Nothing a leader chooses can move a stored figure.

**Anchored copying.** Agreement among models is not enough on its own: several models can make the same mistake. So code checks every copy against the validator's **own** rendering of the page, line by line:

- **The page itself** must print the issuer's name (whole words), the period end and the currency. The period end must be printed to the minute followed by `UTC`, `GMT` or `Z` with no offset (`UTC+04:00`, `CET`, `ET`, `local time` and a bare time are refused), or, for a period that ends at midnight, as its last day in a usual form (`2026-12-31`, `31 December 2026`, `31 Dec 2026`, `31st December 2026`, `December 31, 2026`, and `31.12.2026` or `31/12/2026` only when the day cannot be a month). It must not stand only after a prior-period word (`prior`, `previous`, `comparative`, `compared`, `versus`, `vs`, `preceding`, `restated`, `last year`, `year ago`, as whole words) or after another date on its line, and the page must not print a later period end of the same report on a line that names a past period (`ended`, `six months to`, `year to`: next period's results; an outlook `for the year ending ...` does not count). So a model that writes the expected values for another company's page, for last quarter's, or for next quarter's page that shows this period as its second column, is refused.
- **The label** must be on the figure's closed list and must **start its line, a table cell, a bullet or a numbered item**, ending at a word boundary: `EBITDA` does not anchor inside `Adjusted EBITDA` or `Adj. EBITDA`, `tax profit` not inside `Pre-tax profit`, `revenue` not inside `U.S. revenue`. A numbered item is digits, one letter or a roman numeral (`1.`, `a)`, `iv.`) at the start of the line or cell, so an abbreviation (`Adj.`, `Est.`, `(excl. IFRS 16)`) is not one. A qualifier just before a cell mark or a spaced dash (`Adjusted: EBITDA`, `Non-GAAP - EBITDA`, `Pro forma | EBITDA`, `Prior year: EBITDA`, from a closed list in the contract) does not start a phrase either; only the words right before the mark are checked, so `Adjusted (1): EBITDA`, `Guidance 2027: EBITDA` or `2025: EBITDA` still anchor.
- **The value** must be the **first amount after the label on the same line**, within 160 characters, copied as printed **with its sign**. Between them only separators, the currency, scale words, note references (`note 4`), footnote marks (`¹`, `(a)`, a `*` on the label), percentages (`rose 9% to`) and a short list of linking words (`was`, `rose to`, `for the quarter`, `for the year`, `for the half year`) may stand. So `Revenue per employee 120`, a value from the next row, the prior-period column, an amount in another currency (`$16.2 million (€15.0 million)`), a change before the amount (`increased by EUR 1.3 million`) or after it (a comparative or change word straight after the amount, whatever follows: `EUR 1.3 million higher at`, `greater than`, `up on 2025 at`, `increase from EUR 14.9 million`, `year-over-year increase`, `like-for-like increase`; the same after a bracket or `or` and a percentage: `(9%) higher`, `, or 9 per cent, higher`, `, or 9.3%, higher`; after a comma or a spaced dash, a change word with no percentage or prior amount after it: `, up on the prior year at`, `– a year-on-year increase`. Levels: `EUR 16.2 million, up 9%`, `– up 9.3%`, `, up from USD 14.9 million`, `, an increase of 9 per cent`, `, a 9% increase`, `, 9% higher than`), and the next column behind an empty cell (`–`, `…`, `*`, `.`, `•`, `=`, `(-)`, also with the currency in every cell, `€ – € (1,200)`) are refused. The dash and minus glyphs the contract lists (`MINUS_GLYPHS`: the minus sign, hyphens, figure, en, em and other dashes, the small and full-width hyphen-minus) all read as a minus; a sign printed before the currency (`-€1,200`, `(€1,200)`, `–EUR 1.2 million`) belongs to the value, and any other mark right before the digits (`( 1,200 )`, `△1,200`, `~1,200`) refuses a copy that leaves it out; a spaced dash (`- 1,200`, a minus or an empty cell) is refused either way, and so is an unsigned copy of `1,200-` (a trailing minus). The value must also be a whole number on the page: not part of `21,000`, `1,000.5`, `12%`, a date, `40'000` or `15 240`. Unicode superscript footnote marks (`Revenue¹ 15,240¹`) are dropped on the page and in the copy. A footnote number set in HTML (`48.0<sup>1</sup>`) is another matter: Studio's text rendering glues it to the word before it, and we measured `48.0` with note 1 coming out as `48.01` and `Revenue<sup>1</sup>` as `Revenue1`. Text alone cannot tell `48.01` from 48.0 with a note, so each validator also renders the page as HTML, lists the tokens made by gluing a `<sup>` or `<sub>` mark to the word before it, and refuses a figure whose line holds one (`N2_FORMAT`). The guard is a heuristic: a mark set with a styled span or a plain link, a comment or an unusual tag between the number and the mark, a mark inside brackets, or an HTML rendering that comes back empty is not caught, and a value with such a note can then be stored with the note's digit added (`48.01`).
- **The scale** is tied to the figure. **Totals are never read in whole units**: any figure that is not per share needs a scale, because a scale heading this code does not know would otherwise make it 1,000 times too small. The value's own scale word decides (`EUR 16.2 million`, or `16.2` followed by `million` or a scale glued to the code, `16.2 EURm`, at the place the value was anchored); `mln`, `mill.`, `bln`, `Mrd`, `tsd` and a lone `B` after the value count too, and `trillion`, `tn`, `lakh`, `crore`, `cr` or `mil` (million in English, thousand in Spanish) after it refuse the figure at any scale. Otherwise a heading-type scale on the figure's own line decides (`Total borrowings (EUR million) 48.0`); another amount's scale on that line (`of which EUR 2.5 million restricted`) does not. Otherwise the copied scale words (a scale word, or a heading form such as `(x EUR 1,000)`) must be printed on the page, name the copied scale and no other, be the **only** scale the page's headings name, and the page must name no other scale anywhere, in a heading or in prose. A line names a heading scale with a one-letter scale next to the currency (`€m`, `EURm`, `£'m`, `EUR (m)`, `k€`, `M€`, `T€`, `m EUR`, `k EUR`; `$m` and `$k` only for USD), a scale word within three words of the currency (`EUR thousands`, `NOK mill.`, `Tsd. EUR`, `in Tausend EUR`, `en milliers d'euros`, `millions of euros`), after "in" (`(in thousands)`, `(in thousands of Canadian dollars)`, but not `in thousands of ports`), a plural standing alone (`Thousands`), `TEUR`, `kEUR`, `MEUR` or `Mio`, a multiplier after `x` or `in` (`(x EUR 1,000)`, `in 1.000 EUR`, `(in EUR 1,000, unless otherwise stated)`, `(in 1,000 US dollars)`, `x 1,000,000`), `(000 omitted)`, or a thousands mark (`£000`, `£ 000`, `EUR'000`). Prose such as `a million customers` or `thousands of ports` names none, and neither do `10:00 a.m.`, `M&A`, `I'm`, `401(k)`, `in 1,000 stores`, `per m² EUR 7.25`, `per sq m`, `Class M EUR` or a bare amount (`EUR 1,000`). `mil` anywhere on the page except right after a number (`(EUR mil)`, `R$ mil`: a thousand in Spanish and Portuguese, a million in English) keeps out every copy whose scale comes from the page's headings; a scale printed on the figure's own line still decides. A figure declared `per_share` is decided first: it is read in units only, with the copied scale words exactly the report's currency (the code, its symbol, `euro` or `euros` for EUR, `US$` for USD, also in brackets or after `in`: `EUR`, `€`, `(EUR)`, `(in EUR)`) printed bare on its own line (no letter touching it: not `€` from `(€c)` or `c€`, not `$` from `A$`, and not `EURm`), with no scale named on its line between the label and the value (`Average revenue per unit (EUR thousands) 1,250` refuses), and it never takes a scale, not even one printed on its line after the value (`Dividends paid (EUR m)` beside it). So a sub-unit spelling this code does not list (`(c)`, `€c`) refuses it unless the bare code also stands on the line; `cps`, `fils`, `halalas`, `baisa`, `paise`, `kopecks`, `centimes`, `groszy`, `satang`, `agorot`, `haleru` and `kurus` are listed with pence and cents. Pence or cents (`pence`, `(p)`, `cents`, `¢`) on the figure's line, in the copy or in the column heads just above it (`pence pence`) refuse the figure at every scale: the form has no scale for hundredths. `per cent` is a percentage, not cents.
- **LTM** must be printed on an LTM figure's own line, before the value (LTM, TTM, last or trailing twelve months).

So in every layout above, a figure the model invents, takes from another row or column, signs or scales wrongly is refused before validators even compare. These checks are a list of layouts, not a parser: the Limits section names what they do not cover.

**One official reading, and a clock that never runs backwards.** Every write to a report moves its clock to the transaction's time if that is later, and a reading is handled at the clock's time. Once any write stamped at or after a window's close has been processed, no `READ` can land in that window; until then `get_reading` says `CLOSING`. So `READ` and `MISSING` are final for every consumer, whatever order the network processes transactions in.

### Finality marked by the reader itself

A final answer in the reader's latest (accepted) state can still be appealed until the network finalizes the transaction that wrote it. A consumer must pay only on a finalized answer. On Studio, a view of another contract's finalized state (`view(state=StorageType.LATEST_FINAL)`) did not run: we measured it twice, in live run s2 and in a two-contract probe, and both times the transaction hit the 600-second leader timeout. A message a contract posts to itself with `on='finalized'` did run, right after finalization, and an outside call to it was refused. So ReportReader keeps the mark itself:

- when `read()` records the official `READ`, it posts `confirm_read(report_id, n, hash)` to itself with `on='finalized'`. The network runs it only once that transaction is finalized, appeals included, with the reading that finally stands; it marks the period `finalized` if the hash is the official reading's;
- when a write moves the clock past a window's close with no `READ` (a `tick()`, or any later `read()` that does not fail), it posts `confirm_clock(report_id, clock)` the same way; once it runs, that period's `MISSING` is `finalized`. One `read()` can post both messages;
- anyone may call `remark(report_id, n)` to post a period's mark again if its answer is final but unmarked (a lost message, or a window that closed before the report was registered). On Studio a transaction finalizes only after the older transactions of the same contract (the finalization query in Studio's consensus worker), so the mark still runs only after the write that made the answer final is finalized;
- `confirm_read` and `confirm_clock` refuse any sender but the contract itself.

`get_reading` reports `finalized: true` only after its mark has run. EarnOutExample reads the latest state and settles only on `finalized: true`.

## State design

- `reports: TreeMap[str, Report]`: the canonical specification, its digest, owner and creation time.
- `clocks: TreeMap[str, u256]`: each report's clock.
- `periods: TreeMap[str, str]`: per `report:period`, the official reading (time, reader, page, attempt number and figures), whether its finality mark has run, and the first 20 attempts with the count.
- `final_clocks: TreeMap[str, u256]`: each report's clock as of the latest write whose finality mark has run.
- Figures are integers in stored units, returned as decimal strings so JavaScript clients do not lose precision.

## Guards

- **Prompt injection.** The page sits between markers and is labelled untrusted data; marker-like text is removed and the page is cut to 12,000 characters at its last line break, keeping that last line as printed (a page with no line break in its first 12,000 characters keeps nothing), so no number loses its scale word or is cut in two. Only the fixed form's fields are read. Anchoring means an injected instruction cannot make a validator store a number the page does not print next to its label.
- **URL filter.** `https://` only. Public names and public dotted IPv4 addresses only; no user info, backslashes, IPv6 literals, single-label hosts, numeric tricks, private or link-local ranges, or internal suffixes. Names that carry an address inside them (`127.0.0.1.nip.io`, `10-0-0-1.example.com`), `.localdomain`, and the known wildcard-DNS and DNS-rebinding services are refused; code cannot see where any other name resolves. `{n}` must be in the path.
- **Time.** A reading is refused before its window opens. A call stamped after the close reads nothing and settles the period.

## EarnOutExample: a consumer that moves money

[`examples/consumer/earn_out_example.py`](examples/consumer/earn_out_example.py) is a deferred payment paid on a reported figure. It reads no page and calls no model.

1. **Offer.** The buyer calls `create` (payable) before the period ends and offers the terms: the seller, a report id **and its digest**, the period, a figure, a floor, a target, and `missing_seller_bp`, the seller's share if the report is `MISSING`. The contract checks all of it against ReportReader's latest state with a cross-contract view: the digest must match, the figure and period must exist, the call must be stamped before the period end, the status must be `NOT_DUE`, no reading may exist (even one not yet finalized), and the reader's clock must be before the period end. A refused `create` credits the GEN back instead of reverting. `create` returns the **terms digest**: the sha256 of both parties and every pinned term.
2. **Accept.** The seller calls `accept(deal_id, terms_digest)` under the same conditions, so neither side can sign up once the outcome can be known. Until then the buyer may `cancel`. An offer not accepted before the period end goes back to the buyer at `settle`.
3. **Settle.** Once the answer is final, anyone calls `settle`. It pays only when ReportReader marks the answer **`finalized`** (above), so a reading that could still be appealed never pays; before that it refuses and can simply be sent again:
   - `READ`: the seller gets the escrow on a straight line from the floor (nothing) to the target (everything), rounded down, and the buyer the rest;
   - `MISSING`: the seller gets `missing_seller_bp` / 10,000 of the escrow, rounded down, and the buyer the rest. After a sale the buyer runs the business and its reporting, so a missing report should not pay the buyer. The parties pin this share up front; anything below 10,000 (everything to the seller) is an option the buyer holds, because the buyer can make a period `MISSING`.

   Any other status refuses (`CLOSING` says to send `tick` first).
4. Payouts are credits; each address takes its own with `withdraw()`. `totals()` reconciles the contract's balance as `locked + credited`, once withdrawals have finalized (a withdrawal debits the credit before its transfer message, so a transfer the network dropped would leave the balance above that sum).

## Limits

- **Trust in the published figures and in the host.** A reading says what one public page showed. It trusts the issuer's figures, as a printed report does; whoever controls the page's host controls what is read. Pin the issuer's own investor-relations host. Code cannot see where a DNS name resolves.
- **The closed label list is not a parser.** A label must start its line or cell, but a different line that starts with the same words and goes on only with linking words would still anchor. List exact labels, and avoid short ones.
- **Which table, which column.** Code takes the first amount after the label. It cannot tell the period's table from a year-to-date table with the same label (only the model's `conflicting` answer refuses that), a prior-period-first column order, an empty current cell (a browser's text leaves no trace of it), or prose that names the period after the amount (`was EUR 14.9 million a year ago and EUR 16.2 million this quarter`). Pin a page that shows one table per period, current period first.
- **Layouts that read nothing.** The value must be on its label's line. Labels in one column with values in the next row, a numeric footnote or notes column between the label and the amount (`Revenue (1) 15,240`, unless written `note 4`), a dash between the label and the value (it may be an empty cell), a whole number without separators followed by a three-digit cell (`915 880`), and percentage figures (`EBITDA margin 27.4%`) give `N2_NOT_ANCHORED`: nothing wrong is stored, but nothing is read, and a window that reads nothing ends `MISSING`.
- **Mixed scales and per-share figures.** On a page whose headings name two scales, a figure whose own line names none is refused. A per-share figure needs the copied currency words on its own line, and one in pence or cents (`Basic earnings per share (pence) 12.3`, the usual UK layout) is refused. A per-share figure reads only when the models copy the currency printed on its own line (`EUR`, `(EUR)`, `€`); a copy of a heading's words (`per-share amounts in euros`, `units`) refuses it, and a table that states the per-share currency only in its heading reads nothing for it. We saw this in live run s11, whose demo heading said "except per-share amounts in euros": the period was refused. Even with the currency printed only on the per-share line (run s12), three leaders in a row refused period 0 before the fourth read it. One refused figure refuses the whole reading, so a per-share figure in a report can make every figure of that period `MISSING`: register per-share figures in a report of their own. A per-share figure printed as `(Yen)` is refused too: only the code, its symbol, `euro`/`euros` and `US$` count. A per-unit figure that is not per share but uses the word (`Revenue per business unit`) must be registered per share, so it reads only in units. A line that names a segment `CPS` or `CT` reads as cents and is refused.
- **What can still go wrong.** Each of these stores a wrong figure only if most validators' models make the same slip: a page with two tables in different scales where one heading uses a form this code does not know (`$m` for dollars other than USD, a heading word it does not list), and the figure from that table is copied with the other table's scale; a total printed in whole units in prose (`Revenue for the quarter was EUR 15,240,315.`) on a page whose only heading names thousands, copied as thousands; a per-share figure in a sub-unit this code does not list, printed with the bare code beside it, copied as the code; a per-unit total registered per share (above) whose line prints the currency under a thousands heading on another line, copied in units; a per-share row whose label and hint the author left without any per-share word, registered as a total, copied with the heading's scale; a qualifier the closed list does not hold, set before a cell mark (`Management: EBITDA`), copied as the plain label.
- **Changes and levels.** In `Revenue was EUR 1.3 million higher at EUR 16.2 million` neither amount reads: the first is a change and the level is not the first amount after the label. Nothing wrong is stored, but nothing is read. A level followed by a comparison (`EUR 16.2 million, higher than last year`) is refused too, and so is a level with a change word straight after it and no comma or dash (`EUR 16.2 million up 9%`, `USD 16.2 million increased 9%`, `£16.2m (2025: £14.9m) up 9%`).
- **Totals in whole units are not read.** A report that prints totals without any scale (`Revenue EUR 15,240,000`) reads nothing for them; per-share figures still read. A scale heading this code does not know (a bare `NOK 1000`, `EUR mln`, `EUR bln`, `EUR Mrd`, or a heading word it does not list) also makes a page read nothing, and so does a scale word in prose elsewhere on the page (`millions in savings`, or a first word such as `THOUSAND OAKS, Calif.`). Nothing wrong is stored, but a window that reads nothing ends `MISSING`.
- **Formats the page must print.** The currency code (a `$` alone is shared by many currencies), and the period end as `YYYY-MM-DD HH:MM` with `UTC`, `GMT` or `Z`, or for a period that ends at midnight UTC as its last day in one of the forms above. A page in local time, or one that prints next period's end on a line that names a past period (`ended`, `months to`, `year to`), reads nothing.
- **A period has an end, not a length.** On a fourth-quarter release that prints the quarter first and the full year second, a yearly figure is refused (the first amount after the label is the quarter's) and a quarter copied for it is stored; in prose, `Revenue for the full year was` links while `for the fourth quarter` does not, so a slip can store the year for a quarter. Pin a page with one period per table, or register the quarter.
- **Money only.** A figure is read as an amount of money in the report's currency. A ratio, a head count or a percentage (`Net debt / EBITDA 3.2`, `Employees 1,250`, `EBITDA margin 27.4 %`) on a page whose heading names thousands takes that scale if copied so; a whole-units table under a thousands heading (`Share capital 1,500,000` in a parent-company statement) too. List money figures only, and check the page's tables.
- **What rests on the model alone.** Code checks every copied figure, but three answers have no check in code: whether the page is marked draft (`N3_NOT_FINAL`), whether the period's report is not published yet (`NOT_PUBLISHED`), and whether the page shows the figure twice (`conflicting`). A draft page whose models all answer "not draft" is read; a UK "Preliminary results" title (final figures) may be refused as draft.
- **The first 12,000 characters.** The page is cut there, so a table after it is not read. Most real releases are longer: pin a page that puts the figures first, such as a results summary page.
- **Common false refusals.** A period end printed as a range (`1 July to 30 September 2026`) or after a dateline with a later date, footnote numbers set in HTML on a figure's line, labels with a footnote glued to them, a scale word in an unrelated heading (`in EUR 1,000 denominations`, `tCO2e per EUR m`, `MIL-STD-810`), a `9M 2026` column head, and a list number after another mark (`• 1. Revenue`) make a reading refuse. Nothing wrong is stored, but a window that reads nothing ends `MISSING`.
- **Who reads first** fixes the moment of the official reading within the window. A `NOT_PUBLISHED` attempt binds nothing, so anyone may read again when the report appears.
- **Final, then finalized.** `READ` and `MISSING` never change in ReportReader's logic, but until its transaction is finalized a reading can still be appealed, and an appeal re-reads the page as it then stands. A consumer should act only on `finalized: true`, as EarnOutExample does. If a mark is ever lost, `remark()` posts it again.
- **Bradbury.** On GenVM v0.6 a message posted with `emit()` is paid from the sending transaction's allocations, so on Bradbury `read()` (up to two messages), `tick()` and `remark()` (one each) must carry an internal-message allocation per message, as `withdraw()` carries one for its transfer. The helper in `tools/bradbury/gl.mjs` attaches only the external one for `withdraw()` today. Each reading renders the page twice (as text and as HTML). The v0.6 builds pass the same tests in direct mode; they have not run on Bradbury.
- **Timestamps and rendering.** A reading's time is its transaction's timestamp, and windows and the report clock use it. Validators render the page when the transaction is processed, as text and as HTML: in run s12 a read was accepted 29 seconds after it was sent (median), at most 156 seconds, and up to about 5 minutes when Studio is busy.
- **The demo** compresses a reporting year into minutes and states each period end to the minute; real reports use dates. The demo pages are fictional and hosted on a sister project's site.
